# Document due diligence

This demo keeps text and PDF attachment bytes in application-owned storage while execution records
carry content-addressed `ArtifactReference` values. A reviewer Agent searches extracted text
through a versioned retrieval Tool, builds a cited report and publishes it only after an exact
approval.

Build the workspace, then run the compiled demo on Node.js:

```bash
bun run build
node examples/due-diligence/dist/main.js
```

The default library contains a master services agreement and a renewal amendment. The run prints the
attachment references, pending publication approval, final cited answer, generated JSON report and
the retrieval/publication Calls from Story inspection.

To use provider-native PDF input instead of the deterministic demo model, connect the same library
to an opt-in adapter:

```ts
import { createOpenAIResponsesAdapter } from "@harngine/codex-api";
import { createDueDiligenceDesk, DocumentLibrary } from "./app.js";

const library = new DocumentLibrary();
const model = createOpenAIResponsesAdapter({
  accessToken: "magpie",
  baseUrl: "http://127.0.0.1:3425/v1",
  model: "vision-capable-model",
  resolveArtifact: library.resolve.bind(library),
});
const desk = createDueDiligenceDesk({
  directory: ".harngine",
  outputDirectory: "published",
  library,
  model,
});
```

## Boundaries

- **References, not payloads:** Messages, Work objectives and Context Items carry id, media type,
  byte length and SHA-256 digest. The application owns the bytes and access checks.
- **Model context:** selected attachments appear once in `ModelContext.artifacts`; the model can call
  an application Tool to search extracted text without embedding full documents in ordinary chat
  history.
- **Native PDF input:** `DocumentLibrary.resolve()` verifies and returns application-owned bytes
  without exposing storage to Harngine. An opt-in provider adapter can use it as `resolveArtifact`;
  the adapter verifies the reference again before encoding the PDF in a provider request.
- **Retrieval:** every passage carries an attachment source and content digest, and the final answer
  cites those exact versions.
- **Publication:** `diligence.report.publish` writes the report only after approval. Its output is
  another Artifact Reference with the digest of the generated bytes.

The small in-memory library is demonstration storage. It does not define production binary
storage, authorization, retention, OCR, PDF parsing or a vector database. The app supplies extracted
PDF text beside the bytes. OpenAI Responses and Claude Messages adapters own their provider wire
encoding; Harngine core does not encode provider payloads.
